# 設計：LIFE ROUTE（ライフルート、旧 住まいの一生シミュレーター）

## 1. 背景（#03_商談報告 から）
2026年10月下旬の #03_商談報告 16件をツール（`hearing-risk-analyzer`）で機械的に集計した（個人名は扱わず、件数と分布だけ）。
- 年齢の中央値 27歳（24〜46歳）、年収の中央値 約390万円、家賃の中央値 3万円（実家・低家賃が多い）、貯金の中央値 140万円
- 多いリスク：貯金が少ない（10件）、商談の長期化（9件）、異動・転勤（7件）、車のローン（5件）。結婚に触れた報告 10件
- **老後・年金に触れた報告は1〜2件だけ** → お客様も営業も「持たない場合の老後の住まい」を話していない

お客様ごとに説明がばらつき、「今の家賃と毎月の返済」の比較で終わってしまう。**一生（特に老後30年）の住まいのお金**を、誰にでも同じ順番で見せる型が必要。

## 2. 方針
1. **同じ物差しで2つの道を並べる**：賃貸のまま／持ち家 を、今から95歳まで1年ずつ計算。どちらかを悪く見せない。
2. **持たない場合の「準備」を数字にする**：老後の家賃を年金から払い続ける不足額と、65歳までに必要な積立額。脅すのではなく「知ったうえで選ぶ」。
3. **公平な比較も出す**：差額を運用した場合の額（元本保証なし）。持ち家の家の価値は3シナリオ。
4. **説明の型を固定**：①〜⑥の各ステップに「話すこと・見せる数字・聞くこと」。
5. **入力は選ぶだけ**：お客様の前で迷わない。

## 3. 計算（`lib/engine.js`）
- 暮らしの段階：結婚年齢・子どもの誕生年齢から ひとり／2人／子育て（22年間）／老後（65歳〜）を決め、段階ごとの家賃を使う。
- 持ち家：買う年齢まで賃貸と同じ。購入時に諸費用（ローンに含める設定なら0）、返済年数のあいだ返済、毎年 固定資産税・保険・修繕（20年目から1.5倍）。
- 老後：年金（本人＋配偶者の基礎年金 or 厚生年金）と、生活費＋住居費 の差の不足額を合計。
- 準備：老後の不足額の合計 ÷ 65歳までの月数。
- もしも：団信（残りのローン0）／賃貸なら家族の家賃が続く／金利＋1%の返済額。

## 4. テスト（`npm test`）
返済額、年金の上限、暮らしの段階ごとの家賃、完済後の費用、老後の不足（賃貸＞持ち家）と準備額、一生の住居費と家の価値の大小、団信と金利上昇、公平な比較、結婚しない場合、6ステップの中身、禁止表現。

**正確さの確認（`test/accuracy.test.js`）**：式とは別の方法で計算した答えと突き合わせる。
- ローン：月ごとに残高を追いかけて、完済時に0・各年末の残高が一致。3,000万円・1%・35年＝84,686円。
- 税金：年収390万の手計算（所得268万・課税所得105.5万・所得税52,750円・住民税164,000円）、最低保障74万円・基礎控除104万／67万／62万（令和8年分、財務省「令和8年度税制改正の大綱」）。
- 年金：年収390万・22〜65歳＝847,300＋919,164円。
- 住宅ローン控除：年ごとに 残高×住宅の割合・限度額・物件価格・0.7%・所得税・住民税（課税所得×5%・97,500円）を一つずつ当てはめた額と一致。上乗せは買う年に19歳未満の子がいる（または結婚していて40歳未満）ときだけ。95歳を過ぎた年は数えない。
- 内訳：95歳までに返し終わらない場合も 元金＝借りた額−残り。団信で見直せる生命保険は、65歳までのうち返している年数だけ。
- 324通りのお客様像で、内訳の合計＝一生の住居費、元金＝借りた額、控除≦払った税金、待つ間の家賃、老後の不足が食い違わない。

## 親御さまの反対（バブル崩壊のイメージ）への切り返し（2026年10月追加）
- 「親に相談したら反対された」は、親御さまが1990年前後（バブル崩壊）の住宅ローンと値下がりを見てきたことが多い。否定せず「当時と条件が違う」ことを数字で見せる。
- `BUBBLE`（都市銀行の変動金利の最高 8.5%〔1990〜91年〕・住宅金融公庫 約5.5%）と `bubble(x)`（同じ借入額・年数を当時の金利で計算した毎月の返済と、今の計画の返済）。標準の例：2,996万円・35年 → 8.5%で22.4万円／5.5%で16.1万円／今の1.2%で8.7万円。

## ¥ 節約するなら、いちばん大きな固定費から（2026年10月追加）

## ⑦ 賃貸と購入、どちらがいいか（購入をすすめる設計・2026年10月追加）
- 「どちらが正解ということはない」から、**お客様の数字で購入をすすめる**形に変更。`recommend(x)`：
  - 理由4つ（すべて compute の数字）：一生の住居費（持ち家は65歳に残る家の価値＝横ばいを差し引いた実質）・65歳からの毎月の不足・65歳までに準備したいお金・65歳の資産。
  - 3つ以上が持ち家に有利 → 審査の目安が全部○なら `buy`「購入をおすすめします。まず事前審査で」／△があれば `buyAfterCheck`「購入が合っています。△を見直して事前審査で確かめてから」。2つ以下 → `prepare`「今は賃貸のまま準備」（無理にすすめない）。
  - 注意点は必ず一緒：金利+1%の返済・修繕と税金・値下がり（下落〜上昇）・差額を運用し続けた場合（元本保証なし）・決めるのは金融機関。宅建業法の断定的判断はしない（FORBIDDEN）。
- ⑦の画面：おすすめのバナー（購入＝青／見直し＝金／準備＝灰）＋くらべる表（◎持ち家）＋注意点。問いかけは事前審査へ（prepare のときは積立の相談）。
- ¥ の締めは「家賃として払い続けるか、自分の資産に変えていくか」。提案書4ページ目の見出し＝おすすめ、理由・注意点を先に、賃貸のままの道も残す。
- テスト：`test/recommend.test.js`（8件）。

## 見直して直したところ（2026年10月）
- **買う年齢と今の年齢のずれ**：45歳のお客様で「買う年齢」が初期値の30歳のまま → 計算は「今買う（45歳）」なのに、文章・提案書・資料は「30歳で買った場合」になっていた。`compute()` で買う年齢を今の年齢にそろえ、すべての画面と提案書が同じ年齢を出すように（`test/consistency.test.js`）。
- **スマホの看板**：絵が小さく押しにくい → 看板の下に「はじめる」と各エリアの大きなボタンの列（行き先は絵のボタンと同じ）。
- **グラフのラベル**：一生の住居費のグラフで、持ち家の線が上のとき「賃貸」「持ち家」の金額ラベルが重なっていた → 上の線は線の上、下の線は線の下（文字の幅のぶん左の線の位置より下）に置く。

## 入力は1問ずつ（2026年10月追加）
- はじめて開いたときは、入力を1問ずつ：お客様のタイプ → 年齢 → 年収 → 貯金 → NISA残高 → NISA積立 → 家賃（社宅なら自己負担・出る年齢）→ 物件価格 → 生命保険（毎月・保障額）→ お名前（任意）→ 確認。
- 選択肢が12個以内なら大きなボタン、多いものは大きな選ぶ欄。選ぶと次の質問へ自動で進む。上に「質問 ◯ / ◯」と進み具合。
- 確認画面で答えを一覧にし、押すとその質問に戻れる。金利・老後の生活費などの仮定は「詳しい条件も見る」で全項目の入力へ。説明を始めたあとの「条件を変える」も全項目。

## 独身のお客様の資料2枚目「買うのは、家だけじゃない。」（2026年10月追加）
- 独身（社宅を含む）のお客様の資料は、表紙のあとに絵（趣味に没頭する部屋・仕事に集中する部屋・心からくつろぐ部屋）を1枚。お金の話の前に「自分の好きに使える空間」という暮らしの話から入る。
- 数字は今の家賃と持ち家の毎月の返済を並べるだけ。「修繕や管理は自分で」も同じスライドに書く。結婚・子どもありのお客様には出さない（14枚のまま）。

## お客様の数字は空から（2026年10月追加）
- 年齢・年収・貯金・NISA（残高・毎月）・家賃（社宅なら自己負担と出る年齢）・物件価格・生命保険（毎月・保障額）は、開いたときは「選んでください」。見本の数字（27歳・年収390万…）をお客様に見せないため。
- 空があるあいだは数字の画面（トップ・説明・提案書・資料・画面共有・リンク）を開かず、入力に戻して「あと◯項目」を出す。金利・老後の生活費・再雇用などの仮定は初期値のまま。
- 条件の入った共有リンク（s=）で開いたときは、リンクの条件をそのお客様の数字として使う（空にしない）。前の画面の続きの `#step=3` だけのアドレスでは空から（見本の数字がトップに出ていたため修正）。入力済みの項目は初期値と同じでも必ずリンクに入れる。

## 入力は最初に1回だけ（2026年10月追加）
- スマホでは入力欄がページの先頭にあり、「次へ」で上に戻るたびに入力画面が出ていた → 入力は最初に1回だけ。「この条件で説明を始める」または「次へ」・番号ボタンで畳み、以後は「条件（27歳・年収…）＋条件を変える」の1行だけを表示。
- 「条件を変える」（画面共有モードの「条件を変える」も）で開き直せる。共有リンク（条件入り・ステップ指定）で開いたとき、同じ端末で一度入力を済ませたあと（localStorage に「入力済み」の印だけ。条件やお名前は保存しない）は、リンクを開き直しても最初から畳んで始める。

## お客様に見せる資料を「賃貸より、購入。」に（2026年10月追加）
- 資料（16:9）を、購入をすすめる構成に組み替えた（14枚）：表紙「家賃を払い続けるより、自分の家を。」→ 固定費 → **結論：あなたには、購入をおすすめします** → 理由1 一生の住居費（実質）→ 理由2 老後の毎月 → 理由3 65歳の資産 → 理由4 老後への準備 → 理由5 団信 → 理由6 住宅ローン控除 → 待つと → 親御さまの頃との違い → **購入する前に確認しておくこと（注意点）** → 進め方（まず「できるか」）→ 次の一歩。
- 理由はすべてお客様の数字（`recommend(x)`）。持ち家が有利な項目だけ「理由n」と番号をつける。数字が購入に向かないお客様（`verdict === "prepare"`）には「おすすめ」と書かず、「くらべ」として中立に見せる。
- 注意点のスライドは必ず入れる（宅建業法：断定的判断・不利益の不告知を避ける）。禁止表現は test で確認。
- 見本PDF：14ページ（`npm run deck`）。テスト：`test/deck.test.js`（10件）。

## 「消えるお金」でくらべる・書類と流れ・お客様の保存（2026年10月追加）
- 課題：②で持ち家の合計（例 5,943万）が賃貸（4,998万）より高く見えて、お客様が「買うほうが損？」と迷う。原因は持ち家の合計に家の代金（元金＋頭金）が入っていること。
- `costCompare(x)`：`own.house` = 頭金＋(価格−頭金)×返した割合（`breakdown` の元金÷借入）、`own.spent` = 合計 − house、`rent.spent` = 賃貸の合計。`monthly` = 今の家賃／返済＋(固定資産税＋保険＋1年目の修繕)÷12。talk ② の say・show と画面の3枚のカードに使う。合計どうしのカードは画面では出さず、表の最後の行に残す。
- `SCREEN_DOCS`（CIC・本人確認書類いずれか1つ・源泉徴収票2期分）と `FLOW`（事前審査→内見→売買契約→本申込→金消契約→決済・引き渡し）を `gate()` が返し、⑥・提案書 p4 の次の一歩に出す。
- Zoom（1280×720）では②の内訳表と⑥の人数の箱・CICの細かい説明を省き、1画面に収める（`verify:views`）。
- お客様の保存：`lib/customers.js`（`save`/`remove`/`clear`/`byStaff`/`parse`）。localStorage `lhs_customers_v1` に {id, name, staff, hash, updated}。hash は共有リンクと同じ `share.encode`（開くときは `decode` の検証を通る）。お名前は保存一覧にだけ入り、共有リンク・送信には入らない。開くときはお名前と担当を sessionStorage で1回だけ渡す。名前を変えて保存すると別のお客様として増える。テスト：`test/costflow.test.js`・`test/customers.test.js`。
