# LOAN DESK 社内版 使い方（2026年11月版）

> 対象: 営業部・ローン付け担当
> 社外秘。リンクは代表が「共有」で追加した人だけが開ける。お客様の下の名前・電話・住所は入れない。

## 1. 何ができるか

| 画面 | できること |
| --- | --- |
| お客様と物件 | 条件を入れると、**出す金融機関の順番・保証会社・仲介会社**を出す |
| 申込みの期限 | 決済の月を入れると、**書類→事前審査→本申込み→金消→決済**の期限を逆算する（目安） |
| お客様（全員で共有） | 相談シートのお客様が入っている。開くと条件が入り、順番が出る。担当・姓・県で探せる |
| 否決と再挑戦 | お客様の審査の結果を足すと、**いつ・どこに出し直せるか**と**直すこと**を出す |
| 審査の結果を足す | お客様に紐づかない結果を足す（通過率に入る） |

## 2. 権限

| 共有のときの権限 | できること |
| --- | --- |
| 編集 | お客様の保存・更新、審査の結果の追加、削除 |
| 閲覧 | 見るだけ（保存・削除のボタンは出ない） |

お客様を保存・更新する営業は「編集」で追加してもらう。

## 3. 毎日の使い方

1. お客様を開く（「お客様」の一覧で「開く」）。新しいお客様は、上の条件を入れて、イニシャルか姓と担当を入れて「今の条件を保存」
2. 「出す順番」の1番目から出す。**同時に複数の金融機関には出さない**
3. 結果が出たら、そのお客様の「否決と再挑戦」に足す（金融機関・事前か本審査か・通過か否決か・月・否決の理由）
   - ここに足した結果は、**金融機関ごとの通過率にも自動で入る**。「審査の結果を足す」に同じものを入れなくてよい
   - 否決の理由が分からないときは、金融機関・担当者に確かめてから足す（理由の記録が少ないと、出す前の準備が具体的にならない）
4. 否決されたら、画面の「いつ出せるか」「直すこと」「次に出す順番」に沿って進める
   - 最後の申込みから6か月は、申込みの記録が信用情報に残る（銀行の KSC は1年）。その間は出さずに直すことを進める
   - 否決が3件以上続いたら、借入額・物件・時期のどれかを変えてから出す

## 4. 守ること

- 当社が売主であること、仲介会社との関係（グループ会社を含む）は、最初から金融機関に伝える。名前を出さないために仲介や売主を立てる組み方はしない
- 前に否決されたこと、他の金融機関に出していることは、聞かれたら正直に伝える
- 画面の数字・順番・期限は目安。決めるのは金融機関と保証会社
- 入れてよいのは、イニシャルか姓・担当・条件・審査の結果だけ。下の名前・電話・住所・メモは入れない

## 5. 困ったとき

| こんなとき | すること |
| --- | --- |
| 「全員の一覧にまだつながりません」と出る | 通信を確かめて、ページを開き直す |
| 保存のボタンがない | 閲覧の権限になっている。代表に「編集」を頼む |
| 「保存できる量の上限です」と出る | 使わないお客様を消す |
| パソコンで、ネットにつながらずに使いたい | 1ファイル版（`npm run build` で作る `dist/loan-desk-file.html`）を使う。この版はお客様をその端末にだけ保存する |

## 6. 中身を更新するとき（管理者）

- 通過率の集計: 案件表から `node tools/build-outcomes.js <案件表.csv>`（案件表はリポジトリに入れない）
- 画面の更新: `loan-desk-internal` で `npm test` → `npm run build` → `dist/loan-desk-page.html` を同じリンクに出し直す
- 設計: `loan-desk-internal/docs/設計_共有版.md`
