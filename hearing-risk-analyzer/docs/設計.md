# 設計：ヒアリングから将来のリスクを出し、不動産の価値を伝える

## 1. 目的
#03_商談報告 に書かれたヒアリングは情報が多いのに、「このお客様の将来に何が起きうるか」「だから家をどう持つと良いか」に整理されないまま次の面談を迎えることが多い。貼り付けるだけで、**リスク → 価値の伝え方 → 確認すること → 次にやること** の順に並べ、上席への相談・同行準備・パートナー同席の資料にそのまま使えるようにする。

## 2. 流れ
```
商談報告（テキスト） → parse（項目を取り出す） → analyze（数字・リスク・強み・話の柱） → 画面 / Markdown
```
- `lib/parse.js`：■見出し・「・項目：値」・続きの行・→メモ・〜希望条件〜・✅/⬜ を読む。金額は「5,796,962円／60万／4.6万」を円に。
- `lib/analyze.js`：`RISKS`・`STRENGTHS` のルール表。各ルールは「手がかり（根拠の行を返す）・重さ・将来どうなるか・価値の伝え方・確認すること・次にやること」。
- `lib/report.js`：Markdown にする（CLI と画面のコピー）。

## 3. リスクの考え方
- **根拠を必ず示す**：判定のもとになったヒアリングの行をそのまま出す。営業が「なぜそう言えるか」を説明できるように。
- **重さ**：高＝このままだと契約・審査で止まる（転勤・家族の反対・赤字申告・投資ローン・貯金不足）／中＝家計を圧迫・審査額が下がる／低＝進め方。
- **価値の伝え方は、リスクを打ち消す形で**：転勤 →「住む・貸す・売る」を選べる立地／家族の不安 → 数字と選択肢で答える場／固定費 → 団信で保障の重なりを見直す…。断定・あおりはしない。
- **数字は低い年で見る**：年収が上下している場合は、低い年でも返せる予算を基本にする。

## 4. 個人情報
- 画面もCLIも端末の中だけで処理する。保存しない。
- お客様ごとの分析結果はコミットしない。テスト用のサンプル（`samples/sample.txt`）は架空の人物。

## 5. テスト（`npm test`）
- 金額の読み取り、年収の推移、希望条件、書類の数（段階ごと）
- サンプルから期待する10件のリスクと3件の強みが出る／根拠と5項目がそろう／高いものから並ぶ
- 2行に分かれたパートナーの不安を拾う／今の段階の書類だけでリスクを判定
- 借りられる額・返済比率・家賃からの増え方の計算
- 禁止表現がない／氏名をレポートに出さない／情報が少なくても落ちない
