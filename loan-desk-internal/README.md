# LOAN DESK 社内版（社外秘・公開しない）

当社の住宅ローン審査の実績と、公開版 LOAN DESK の審査エンジン（`../loan-screening-app/lib/`）を組み合わせて、**どの金融機関にどの順番で出すか**と**仲介に入ってもらう会社**を出す社内ツールです。

- 開き方: リポジトリを取得したうえで `loan-desk-internal/index.html` を直接開く。公開版のエンジンを相対パスで読むので、フォルダの位置関係を変えない
- テスト: `cd loan-desk-internal && npm test`（67）
- **公開しない。** GitHub Pages・Netlify の公開設定には入れていない。追加もしない

## 仕組み

順番は次の3つを掛け合わせて決める（`lib/recommend.js`）。

1. **当社の実績の通過率**: ウィルソン下限（z=1.64）で、件数が少ない金融機関ほど控えめに見る
2. **審査エンジンでの相性**: 金融機関の型で審査した結果。承認見込み 1／条件付き 0.8。保留と否決見込みは候補から外す
3. **地元の金融機関か**: 物件と同じ県が地元なら ×1.1

実績が2件以上あって通過が2割以下の金融機関は「最初には出さない」に入れる。申込みは1行ずつで、同時には出さない。当社が売主であることと、仲介会社との関係は金融機関に伝える。

## 保証会社（保証機関）

`data/guarantors.js` に、保証会社と「金融機関 → 保証会社」の対応を入れている。根拠は 社内記録／公開情報／要確認 のどれかで、すべての対応に付けている。

- 画面で「否決された金融機関」にチェックを入れると、その保証会社を否決済みとして覚える（確定しているルートが1つの金融機関だけ）
- 同じ保証会社しか使わない金融機関は外す。別のルートがあるなら残し、「どのルートで出すか」を表示する
- 出す順番は、2番目以降を別の保証会社の金融機関にする
- 詳しくは `経営管理/07_業務管理/業務マニュアル/案件創出/ローン付け/住宅ローンの保証会社_202610.md`

## 否決の記録と通過率（v2）

- `data/outcomes.js` = 金融機関ごとの **事前／本審査／単身** の通過・否決の件数と **否決の理由**（件数だけ。お客様の行・名前・日付は入れない）。`node tools/build-outcomes.js <案件表.csv>` で、リポジトリの外にある案件表から作る。手で直さない
- `lib/outcomes.js`: 理由のタグ（`REASONS`、銀行審査状況パイプライン運用ガイド 6章＋保証会社・業者・信用情報）、表記ゆれ（`ALIAS`）、集計と記録の合算（`merge`）、`statsOf`・`reasonSummary`
- 順番の通過率はこの集計から出す（`lenders.js` の件数と一致することをテストで確認）。単身のお客様では、単身の記録が2件以上で通過2割以下の金融機関も「最初には出さない」に入る
- 上位の候補の否決の理由から、出す前の確認（接道・充て物・雇用の書類・団信の告知 など）を足す
- 画面の「審査の結果を足す」: 金融機関・段階・結果・理由・単身・月だけを、この端末（localStorage `ldi_records_v1`）に足す。すぐ順番に反映。「書き出す」で JSON にして集計担当に渡し、案件表に入れて `build-outcomes.js` を回す。書き出したファイルはリポジトリに入れない
- 2026/10 時点で、否決48件のうち理由の記録があるのは16件。否決が出たら24時間以内に理由のタグを残す

## お客様

- 呼び名（イニシャル S.T か、姓＝漢字・かな4文字まで）と担当、上の入力だけを、この端末（localStorage `ldi_customers_v1`）に保存する。下の名前・電話・長い文字列は断る（`lib/customers.js`、テストあり）
- 同じ姓・同じ担当の別のお客様がいるので、相談シートの掲載日も見分けに使う
- 一覧に、それぞれの第一候補と判定を出す。姓・担当・県で探せて、担当で絞れる。「開く」で条件を戻して順番を出し直す
- **相談シートの全員を入れる**: `node tools/export-customers.js <sheets.json> <リポジトリの外のフォルダ>` → `loandesk_customers_YYYYMMDD.json` を画面の「読み込む」で入れる。借入額などの前提は `tools/sheet-map.js`（`run-sheets.js` と共通）
- 「書き出す」で同じ形のファイルになり、ほかの端末に「読み込む」で移せる（同じお客様は新しいほうを残す）
- このファイルには姓と条件が入る。**リポジトリに入れない**（`.gitignore` 済み）、外部のサービスに上げない

## 共有版（claude.ai のページ）

同じ `index.html` が、置き場所で2通りに動く（設計と計画: `docs/設計_共有版.md`）。

- **ファイル版**（直接開く／`dist/loan-desk-file.html`）: お客様はその端末にだけ保存
- **共有版**（claude.ai の非公開ページ）: お客様の一覧をページの共有データに保存し、共有した全員に反映する
  - 「編集」で共有した人は保存・履歴の追加・削除ができる。「閲覧」の人には、そのボタンを出さない
  - 書き出しはページの保存機能（確認が出る）と、画面に出す内容のコピー。削除は2回押し
- `lib/sync.js`: 共有データの行の名前（`docId`）、差分だけ書く（`diff`）、読んだ行を `customers.js` と同じきまりで整える（`fromSnapshot`）、見出しと見るだけの判定（`viewState`）
- 作り方: `npm run build` → `dist/loan-desk-file.html` と `dist/loan-desk-page.html`（`dist/` はリポジトリに入れない）。共有版は `loan-desk-page.html` を同じページに出し直す。ページの機能は db・user・downloads
- 共有データには姓・担当・条件・審査の履歴が入る。共有する相手は社内の担当者だけにする

## 否決と再挑戦

- お客様を「開く」と「否決と再挑戦」が出る。申し込んだ結果（金融機関・段階・結果・月・否決の理由）を履歴に足すと、次を出す（`lib/retry.js`、テストあり）
  - **いつ出せるか**: 最後の申込みから6か月（CIC・JICC の申込情報）。銀行の KSC は照会の記録が1年残ることも添える。月が分からなければ本人開示で確かめる
  - **直すこと**: 否決の理由ごとの対策。否決が3件以上なら最初に「同じ条件のまま出さない」（銀行審査状況パイプライン運用ガイド 6章）
  - **次に出す順番**: 否決済みの金融機関と、同じ保証会社しか使わない金融機関を外す。待つ間は、直近の否決が記録から外れたあとの順番を出す
  - **出さない先**: 否決のあとに同じ金融機関で通っていれば外さない
  - 前に否決されたことは、聞かれたら正直に伝える。再挑戦も1行ずつ
- 一覧の「否決ありだけ」で、再挑戦するお客様だけを出す（否決の件数と、いつから出せるかを表示）
- 過去の否決の人を入れる: `node tools/export-retry.js <案件表.csv> <名前の対応.json> <sheets.json> <リポジトリの外のフォルダ>` → `loandesk_customers_retry_YYYYMMDD.json` を「読み込む」。本審査まで通った人は除く。相談シートの同じお客様には履歴が足される（読み込みは履歴を合わせる）
- 履歴に入るのは金融機関・段階・結果・月・理由のキーだけ。メモや名前は入らない

## 申込みの期限

- 「決済の目安（月）」を入れると、1位の金融機関の型で逆算して 書類→事前審査→本申込み→金消→決済 の日付を出す（`lib/schedule.js`）。月だけなら25日（土日は前の金曜）
- 日数は社内の目安の長いほう（銀行審査状況パイプライン運用ガイド 2.2、信金は全体で約4週）。否決されたときに次へ出す余裕があるかも出す
- 目安で約束ではない。出す前に金融機関の担当者に確認する

## データ

`data/lenders.js` に、金融機関ごとの通過と否決の件数、営業地域の目安、実績のある仲介会社を入れている。**お客様の情報は入れない**（テストで確認）。

- 出典: Slack `#21_住宅ローン審査報告`（否決一覧 2024/7〜2026/4）、`#37`・`#05`・`#16`、営業報告ログ（2026/3〜9）
- 数え方: 申込みごとに「通過」と「否決」を1回ずつ数える。事前審査と本審査は別に数える
- 更新するとき: 件数を足して `DATA_AS_OF` を変え、`npm test` を通す

## 答え合わせ

公開版の審査エンジンは、同じデータで答え合わせをして基準を直した。結果は `LSA.CALIBRATION` に入っていて、画面の下にも出る。

| | 直す前 | 直した後 |
| --- | --- | --- |
| 一致（25件） | 16件 | 22件 |
| 実際の否決を当てた数（8件中） | 1件 | 5件 |

直した基準は次の4つ。

- 契約・派遣社員でも勤続2年以上なら ○
- 労働金庫型を追加
- 直近6か月の否決 1件は △、2件以上は ×
- 単身で購入動機書がない場合は △

外れた3件は、物件の問題と、否決が続いた最初の1件だった。件数がまだ少ないので、増えたら測り直す。

お客様単位の答え合わせのデータは、名前を伏せていてもリポジトリに入れない。
