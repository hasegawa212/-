# LOAN DESK 社内版：共有版の設計と計画（2026-11）

## 1. 目的

営業部の全員が、同じお客様の一覧（姓・担当・条件・審査の履歴）を見て更新できるようにする。
これまでは、お客様は読み込んだ端末にしか残らなかった。

## 2. 前提と制約

- 置き場所は claude.ai の非公開ページ（Artifact）。持ち主が「共有」で相手を追加する。GitHub Pages・Netlify には出さない（社外秘）
- ページの共有データ（db）は、権限で書けるかが決まる。「閲覧」は読むだけ、「編集」は読み書き
- このページでは、ダウンロード・`confirm()`・`print()` が使えない
- 同じ `index.html` を、次の2つで使う
  - **ファイル版**（リポジトリから直接開く／1ファイルにまとめて配る）：今までどおり、その端末だけに保存する
  - **共有版**（claude.ai のページ）：共有データに保存し、全員に反映する

## 3. 設計

| 部品 | 役割 | テスト |
| --- | --- | --- |
| `lib/sync.js`（新規・純関数） | `docId(id)`：お客様の id（日本語・`|` を含む）を共有データで使える文字（`c`＋16進8桁）にする。`diff(synced, customers)`：前に同期した内容と今の一覧を比べ、保存する行・消す行を出す。`fromSnapshot(docs)`：共有データの行を、`customers.js` と同じきまりで整えて一覧にする。`viewState({shared, canWrite})`：見出し・説明・見るだけかを決める。`errorText(code)`：保存できなかったときの文 | `test/sync.test.js` |
| `index.html` | 保存はすべて `persist()` を通す。共有版なら `diff` の結果だけを書き、ファイル版なら今までどおり端末に保存する。共有データの変更は全員の画面に反映する（10秒つながらなければその旨を出す） | `test/page.test.js`（静的な検査） |
| 書き出し | ダウンロードに加えて、画面に内容を出す（コピーできる）。共有版ではダウンロードが動かないため | `test/page.test.js` |
| 削除の確認 | `confirm()` をやめ、2回押すと消える（1回目で「本当に消す」に変わる） | `test/page.test.js` |
| テーマ | `:root[data-theme="dark"]` を足し、ページの表示設定に合わせる | `test/page.test.js` |
| `tools/bundle.js`（新規） | `--target file`：スクリプトを1ファイルに入れる。`--target page`：さらに `<!DOCTYPE>`・`<html>`・`<head>`・`<body>` を外して、claude.ai のページとして出す。出力は `dist/`（リポジトリに入れない） | `test/bundle.test.js` |

### 守ること

- お客様の行には、決めた項目だけを入れる（`customers.js` の `clean` を通す）。共有データから読んだ行も同じきまりで整える
- 「閲覧」の人には、保存・読み込み・履歴の追加・削除のボタンを出さない。書けるかが分からないとき（`null`）は出しておき、断られたら文で知らせる
- 出力（`dist/`）とお客様のファイルはリポジトリに入れない

## 4. 計画（TDD の順）

1. `test/sync.test.js` を書く → 失敗を確かめる → `lib/sync.js` を作る
2. `test/page.test.js` を書く → 失敗を確かめる → `index.html` を直す（persist・共有・閲覧だけ・書き出し・2回押し・テーマ）
3. `test/bundle.test.js` を書く → 失敗を確かめる → `tools/bundle.js` を作る
4. `npm test` がすべて通る。iPhone 幅（390px）でファイル版を Playwright で確かめる（読み込み・書き出し・削除・再挑戦）
5. `npm run build` で共有版を作り、同じリンクに出し直す。共有データを「閲覧」の権限で読めることを確かめる
6. README・CLAUDE.md を更新し、プルリクエストを出す
