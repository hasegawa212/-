# 役割マップ｜設計と計画

株式会社 Martial Arts の「誰が・何を・どれくらいやっているか」を、Slack（2026年9〜10月）の実際の動きから1枚にまとめる。立候補制度（`経営管理/05_人事・労務/評価・教育/`）で席を決めるときの **事実の土台** にする。

## 1. 目的

- 役職や資料上の役割ではなく、**Slack で実際にやっている仕事** を人ごとに並べる
- 次の3つをひと目で見つける
  1. **担当なし**：誰も持っていない仕事
  2. **1人だけ**：控え（副）がいなくて、その人が休む・辞めると止まる仕事
  3. **代表に集中**：代表が自分でやっている実務（承認以外）
- 立候補制度の席（E-0〜E-8・S-1〜S-10・M-1・P-1〜2・K-1〜5）と結びつけ、「この席が埋まれば、どの仕事が誰から外れるか」を見えるようにする

## 2. データ（`data/roles.js` が唯一の元データ）

```js
{
  asOf: "2026-10-28",
  people: [{ id, name, title, dept, status }],   // status: 在籍 | 新人 | 業務委託 | 退職
  tasks: [{
    id, name, area,            // area: 営業 | 仕入れ・業務 | 管理 | 経営 | 全社
    freq,                      // 毎日 | 毎週 | 毎月 | 都度 | 単発
    owner,                     // people.id か null（担当なし）
    helpers: [],               // people.id の配列（控え・一緒にやる人）
    seat,                      // 対応する立候補の席 ID（なければ null）
    evidence: [{ channel, date, note }],  // 最低1件
    confidence,                // 確認 | 推測
    issue                      // 止まっている・代表に集中 など（任意）
  }]
}
```

- 顧客名・電話・住所・金額は入れない（必要なら「顧客A」）
- 個人の検査スコアや評価は入れない（事実＝やっている仕事だけ）

## 3. 計算（`lib/rolemap.js`、UMD・依存ゼロ、ブラウザでは `RM`）

| 関数 | 返すもの |
| --- | --- |
| `validate(data)` | エラーの配列（ID重複・存在しない人・evidence なし・不正な area/freq・owner が helpers にも入っている） |
| `byPerson(data)` | 人ごとの `{ person, main[], help[], counts:{main,help,total}, weight, mainWeight, level }`。重みは頻度（毎日5・毎週3・都度2・毎月1・単発1）。`mainWeight` は主担当の合計、`weight` は手伝い込みの合計。`level` は主担当だけで決める：`重い`(主が6件以上か mainWeight≥20)・`ふつう`・`軽い`(主1件以下)。全員でやる共通業務（勤怠・給油など）の手伝いで全員が「重い」にならないため。並びは mainWeight の大きい順 |
| `gaps(data)` | 担当なし（owner が null）の仕事 |
| `single(data)` | 担当が1人で控えがいない仕事（`freq` が 毎日/毎週 のものを先に） |
| `ceoLoad(data, ceoId)` | 代表が主担当の仕事 |
| `byArea(data)` | 部門ごとの件数・担当なし件数・1人だけ件数 |
| `bySeat(data)` | 立候補の席ごとに、関係する仕事と今の担当者 |
| `summary(data)` | 上の数字をまとめたもの（人数・仕事数・担当なし・1人だけ・代表集中） |

ルールはこのファイルだけ。画面（`index.html`）とレポート（`tools/report.js`）は表示するだけ。

## 4. 画面（`index.html`、ファイルを直接開けば動く）

1. 数字の帯：人数・仕事の数・担当なし・1人だけ・代表に集中
2. 気をつける仕事：担当なし → 代表に集中 → 1人だけ（毎日・毎週を上に）
3. 人ごとのカード：主の仕事・手伝う仕事・重さ。押すと根拠（チャンネル・日付）が出る
4. 仕事の一覧：部門・頻度・担当で絞り込み
5. 立候補の席との対応

通信なし・保存なし（`fetch` も `localStorage` も使わない）。

## 5. 計画（TDD）

1. **テストを先に書く**（`test/rolemap.test.js`）：小さな架空データで各関数の期待値を固定 → 失敗を確認
2. `lib/rolemap.js` を実装してテストを通す
3. **本物のデータ**（`data/roles.js`）を Slack の調査から作る → `test/data.test.js` で `validate` がエラー0、全員に仕事が1件以上、全タスクに根拠がある、顧客名らしき文字列がない、を確認
4. `tools/report.js`（Markdown レポート）と `index.html` を作る
5. `npm test` が全部通ることを確認 → Playwright で画面を1回確認

## 6. 動かし方

```
cd role-map
npm test                      # node --test
node tools/report.js > report.md   # Markdown の報告
open index.html               # 画面（直接開く）
```

## 割り当て案（handoff）

代表の仕事と担当なしの仕事を、それぞれ次のどれかに分ける。案は `data/handoff.js`（仕事 id → `{ kind, seat?, note? }`）、席の名前は `data/seats.js`。

| kind | 意味 | seat |
| --- | --- | --- |
| `move` | 席に渡す | 必須 |
| `keep` | 代表に残す | なし |
| `rule` | 全員のルールにして、守られているかを見る席を決める | 必須 |
| `stop` | やめる | なし |

- `handoff(data, plan, ceoId)` → `{ errors, missing, count, bySeat: { 席: { move[], rule[], helpers[] } }, ceoBefore, ceoAfter[] }`
- 案は**席だけ**を決め、人の名前は書かない（誰が座るかは立候補で決める。テストで名前が入っていないことを確かめる）。`helpers` は move の仕事を今手伝っている人で、参考として出すだけ
- 代表でも担当なしでもない仕事への案、存在しない仕事、席のない move/rule、不正な kind はエラー。対象の仕事に案がなければ `missing`
- 代表だけが見る資料（社員向けには出さない）

## 別紙「席ごとのやること」（社員に配る紙）

- `npm run sheet`：HTML（`tools/seat-sheet.js --write`）→ PDF（`tools/seat-sheet-pdf.js`）→ パックの組み直し（`tools/build-pack.py`）
- 公募のすべての席を載せる。案で仕事がない席は「職務は公募一覧のとおり」と書く
- パックは `立候補パック_営業部_本体.pdf`（元の10ページ。直接編集しない）＋最新の別紙から毎回作るので、何度実行しても同じページ数
- テスト：全席・全仕事がのる／人の名前（名字すべて・2文字以上の名）・代表に残す仕事・今手伝っている人が出ない／リポジトリの HTML が生成結果と同じ／`esc` が4文字を置き換える
